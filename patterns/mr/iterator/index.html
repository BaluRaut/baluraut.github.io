Behavioral पॅटर्न

Iterator पॅटर्न प्रत्यक्षात कसा काम करतो

संग्रह (collections) अनेक आकारांचे असतात: arrays, linked lists, trees, hash tables. Iterator पॅटर्न तुम्हाला त्या सर्वांमधून फिरण्याचा एकच एकसमान मार्ग देतो, संग्रह घटक कसे साठवतो हे कधीही न दाखवता एका वेळी एक घटक उघड करतो. फिरण्याचे तर्कशास्त्र (traversal logic) एका वेगळ्या cursor object मध्ये राहते, त्यामुळे संग्रह साधा राहतो आणि clients त्याच्या अंतर्गत रचनेपासून वेगळे (decoupled) राहतात.

01 - काय

Iterator पॅटर्न म्हणजे काय?

Iterator हा एक behavioral design पॅटर्न आहे जो एखाद्या aggregate object च्या घटकांना त्याची अंतर्निहित रचना उघड न करता क्रमवार प्रवेश करण्याचा मार्ग देतो. फिरण्याची स्थिती, म्हणजे तुम्ही संग्रहात कुठे आहात, ही संग्रहातून बाहेर पडून एका लहान समर्पित cursor object मध्ये जाते. हे एकच indirection एका client ला list, tree किंवा stream वर एकसारख्याच कोडने फिरू देते.

🎯 एकसमान फिरणे

संग्रह काहीही असो - array, set, tree, किंवा database cursor - clients एकाच interface मार्फत next() घटक मागतात.

🔒 झाकलेली अंतर्गत रचना

संग्रह त्याचे buckets, nodes किंवा index गणित कधीही बाहेर पडू देत नाही. कॉल करणाऱ्यांना घटक दिसतात, ते साठवणारी data structure नाही.

🧭 बाहेर काढलेली स्थिती

प्रत्येक iterator स्वतःची स्थिती धरतो, त्यामुळे एकाच संग्रहावरील अनेक फेऱ्या एकमेकांना अडथळा न आणता एकाच वेळी चालू शकतात.

02 - का

Iterator पॅटर्न का अस्तित्वात आहे

त्याशिवाय, प्रत्येक संग्रहाला त्याचे आतील भाग - indexes, node pointers, hash buckets - उघड करावे लागतील, आणि प्रत्येक client वेगळा loop हार्डकोड करेल. Iterator फिरणे एका interface मागे नेतो जेणेकरून रचना मुक्तपणे बदलू शकतात आणि clients तसेच राहतात.

🧩 एकच फिरण्याचे interface

कोणत्याही संग्रहावर चालणारा एकच loop लिहा. ArrayList ऐवजी TreeSet टाका आणि कॉल करणारा कोड अजिबात बदलत नाही.

🛡️ Encapsulation चे संरक्षण

कॉल करणारे अंतर्गत indices किंवा nodes ला कधीही स्पर्श करत नाहीत, त्यामुळे संग्रह कोणालाही न मोडता tree पुन्हा balance करू शकतो किंवा array चा आकार बदलू शकतो.

🔀 एकाच वेळी अनेक फेऱ्या

प्रत्येक iterator स्वतःची स्थिती वाहून नेत असल्याने, तुम्ही एकाच संग्रहावर nested loops किंवा parallel scans स्वतंत्रपणे चालवू शकता.

🌊 Lazy आणि अनंत क्रम

iterator मागणीनुसार घटक गणू शकतो, त्यामुळे तुम्ही streams, paginated APIs किंवा अनंत ranges प्रत्यक्षात साकार न करता मॉडेल करू शकता.

सोप्या शब्दांत

उपमांसह Iterator चे स्पष्टीकरण

एकच कल्पना, ती चित्रित करण्याचे चार मार्ग, जेणेकरून तुम्ही कोणीही असाल तरी ती नीट समजेल.

🎓 विद्यार्थ्यासाठी

तो एक बुकमार्क आहे. पाठ्यपुस्तकाला तुम्ही कुठे थांबलात हे आठवत नाही, बुकमार्कला आठवते. तुम्ही मित्राला त्याच्या स्वतःच्या बुकमार्कसह पुस्तक देऊ शकता, आणि तुमच्यापैकी कोणालाही आपली जागा हरवत नाही.

👩‍💻 डेव्हलपरसाठी

तो object आहे जो for-each loop गुप्तपणे मागतो. for (x of coll) हे coll.iterator() कॉल करते नंतर संपेपर्यंत next(); त्यामागील array indices तुम्हाला कधीही दिसत नाहीत.

🏢 व्यावसायिकासाठी

एका TV रिमोट चा विचार करा. चॅनेल बटण "next" आणि "previous" म्हणते, पण खाली चॅनेल्स cable वर आहेत, satellite वर की streaming वर हे तुम्हाला माहीत नसते.

🍽️ रोजच्या जीवनातील आवृत्ती

दुकानाच्या काउंटरवरील टिकीट डिस्पेन्सर. प्रत्येकजण क्रमाने पुढचा नंबर एका वेळी एक ओढतो, आणि मशीनच्या आत तिकिटांची गुंडाळी कशी गुंडाळलेली आहे हे कोणालाही पाहण्याची गरज नसते.

03 - कसे

ते पडद्यामागे कसे काम करते

संग्रह एक factory method उघड करतो जी नवीन cursor परत करते. cursor एक स्थिती धरतो, "अजून आहे का?" याचे उत्तर देतो, आणि पुढे सरकत सध्याचा घटक परत करतो. client फक्त त्या cursor interface शीच बोलतो.

🚶 External iterator

client loop चालवतो: तो स्वतः hasNext() आणि next() कॉल करतो. कमाल नियंत्रण, त्यामुळे तुम्ही थांबवू शकता, डोकावू शकता किंवा दोन iterators एकमेकांत गुंफू शकता. हे Java चे Iterator आणि JavaScript चे iterator protocol आहे.

🔁 Internal iterator

संग्रह loop चालवतो आणि प्रत्येक घटकासाठी तुम्ही दिलेली function कॉल करतो, जसे forEach किंवा Stream.map मध्ये. कमी boilerplate, पण तुम्ही सहजपणे लवकर थांबू शकत नाही किंवा दोन फेऱ्या एका तालात चालवू शकत नाही.

Java मध्ये एक custom iterator

import java.util.Iterator;
import java.util.NoSuchElementException;

// Concrete Aggregate: exposes iterators without revealing the array
public class NameRepository implements Iterable<String> {
    private final String[] names = { "Ada", "Alan", "Grace", "Linus" };

    @Override
    public Iterator<String> iterator() {
        return new NameIterator();       // factory method
    }

    // Concrete Iterator: an inner class holding the traversal state
    private class NameIterator implements Iterator<String> {
        private int index = 0;           // externalized cursor position

        @Override
        public boolean hasNext() {
            return index < names.length;
        }

        @Override
        public String next() {
            if (!hasNext()) throw new NoSuchElementException();
            return names[index++];       // read, then advance
        }
    }
}

// Client: uses the interface, never the array
class Demo {
    public static void main(String[] args) {
        NameRepository repo = new NameRepository();
        for (String name : repo) {       // for-each calls iterator() + next()
            System.out.println(name);
        }
    }
}

NameRepository हे Iterable implement करत असल्याने, वर्धित for loop आपोआप चालतो: compiler त्याचा विस्तार iterator(), hasNext(), आणि next() च्या कॉलमध्ये करतो. index iterator मध्ये राहतो, repository मध्ये नाही, त्यामुळे एकाच repo वरील दोन loops कधीही टक्कर घेत नाहीत.

04 - Sequence आकृत्या

सविस्तर sequence आकृत्या

तीन दृश्ये: एक external फिरणे, एक internal iterator, आणि loop च्या मध्येच संग्रह बदलल्यास fail-fast शोध.

एका aggregate object पासून पूर्णपणे वापरलेल्या, decoupled फिरण्यापर्यंत, संपूर्ण प्रवास क्रमाने.

Model

फिरण्यासाठी एक संग्रह असणे

तुम्ही एखाद्या aggregate ने सुरुवात करता: array, linked list, tree, किंवा API कडून पानांचा stream, ज्यामधून client ला घटक-दर-घटक फिरायचे असते.

10

iterator चा करार ठरवा

फिरण्याच्या methods घोषित करा, विशेषतः hasNext() आणि next(), जेणेकरून रचना काहीही असो, प्रत्येक walker कॉल करणाऱ्यांना सारखाच दिसतो.

एक factory method जोडा

संग्रहाला Iterable implement करायला लावा, ज्यात एक iterator() method असते जी मागणीनुसार नवीन cursor तयार करते.

30
Cursor

concrete iterator लिहा

एक लहान class implement करा जी सध्याची स्थिती धरते आणि या विशिष्ट रचनेतून कसे पुढे सरकायचे हे जाणते.

40
State

स्थिती बाहेर काढा

index किंवा node pointer iterator मध्ये साठवा, संग्रहात नाही, जेणेकरून अनेक iterators अडथळ्याशिवाय एकत्र राहू शकतात.

Client iterator मागतो

client iterator() कॉल करतो. त्याला पहिल्या घटकाच्या आधी ठेवलेला cursor मिळतो आणि अंतर्गत रचनेबद्दल त्याला काहीही माहीत नसते.

60
Check

hasNext विचारा

प्रत्येक वाचनापूर्वी client hasNext() कॉल करतो. iterator अजून भेट द्यायचे घटक शिल्लक आहेत का हे कळवतो.

70
Advance

next कॉल करा

client next() कॉल करतो, जे सध्याचा घटक परत करते आणि cursor एका स्थानाने पुढे सरकवते.

80
Guard

concurrent बदल शोधा

fail-fast iterator एका modification counter ची तुलना करतो; loop दरम्यान संग्रह बदलला तर तो भ्रष्ट data परत करण्याऐवजी अपवाद फेकतो.

90
Exhaust

शेवटी पोहोचा

hasNext() अखेरीस false परत करते. loop स्वच्छपणे थांबतो आणि client next() कॉल करणे बंद करतो.

100
Reuse

संग्रह मुक्तपणे बदला

client ने फक्त iterator interface ला स्पर्श केल्याने, तुम्ही अंतर्निहित रचना कोणत्याही दुसऱ्या Iterable ने बदलू शकता आणि loop तरीही चालतो.

सामान्य अडचणी

अडचणी आणि anti-patterns

state, mutation आणि laziness एकत्र येईपर्यंत iteration क्षुल्लक वाटते. हे नेहमीचे गुन्हेगार आहेत.

💥 Iteration दरम्यान बदल करणे

loop दरम्यान संग्रहामार्फत घटक जोडणे किंवा काढणे cursor भ्रष्ट करते. iterator चे स्वतःचे remove() वापरा किंवा बदल गोळा करून नंतर लागू करा.

♻️ संपलेला iterator पुन्हा वापरणे

बहुतेक iterators एकाच फेरीचे असतात. एकदा hasNext() false झाला की तो false च राहतो. संपलेला पुन्हा वापरण्याऐवजी नवीन फेरीसाठी पुन्हा iterator() कॉल करा.

🕳️ तरीही अंतर्गत रचना बाहेर पडणे

next() मधून backing array किंवा जिवंत node परत करणे मूळ हेतूच नष्ट करते. तुमच्या रचनेतील references नव्हे, तर मूल्ये किंवा defensive copies परत करा.

🔁 अंगभूत गोष्टींचा पुनर्शोध

भाषा आधीच Iterable, generators किंवा streams देत असताना हाताने cursor बनवणे bugs वाढवते. standard protocol implement करा जेणेकरून for-each सहज चालेल.

🧵 एकच iterator अनेक threads मध्ये वाटणे

Iterators बदलणारी स्थिती वाहून नेतात आणि thread-safe नसतात. प्रत्येक thread ला स्वतःचा द्या, किंवा वाटलेल्या फिरण्यासाठी बनवलेला concurrent collection वापरा.

⏳ laziness चे परिणाम विसरणे

generators आणि streams सोबत, तुम्ही ओढेपर्यंत काहीही चालत नाही. फेरी कधीच पूर्ण झाली नाही तर deferred काम कधीच घडत नाही आणि थांबण्याच्या अटीशिवाय अनंत क्रम अडकून राहतात.

तडजोडी

तडजोडी आणि कधी वापरावे

Iterator हा शांतपणे सर्वत्र असणाऱ्या पॅटर्नपैकी एक आहे. तो कुठे फळतो आणि कुठे गोंधळ वाढवतो ते येथे आहे.

पैलूतपशील
फायदेएकसमान फिरणे, अंतर्गत रचना झाकते, एकाच वेळी अनेक फेऱ्यांना आधार देते, आणि lazy किंवा अनंत क्रम शक्य करते.
तोटेअतिरिक्त objects आणि indirection, एकाच फेरीचे semantics आश्चर्यचकित करू शकतात, आणि साध्या array loop साठी custom iterator अतिरेक ठरतो.
कधी वापरावेतुमच्याकडे नॉन-ट्रिव्हियल किंवा custom रचना असेल, तिची मांडणी झाकायची असेल, lazy evaluation हवे असेल, किंवा अनेक फिरण्याचे क्रम द्यायचे असतील.
कधी टाळावेarray किंवा list वरील साधा indexed loop अधिक स्पष्ट असेल, किंवा संग्रह अगदी लहान असेल आणि त्याची रचना बदलणार नसेल.
गुंतागुंतकमी. दोन methods आणि एक position field. सूक्ष्मता fail-fast checks, laziness आणि thread-safety मध्ये आहे, मूळ loop मध्ये नाही.
संबंधितComposite (tree एकसमानपणे फिरा), Visitor (प्रत्येक घटकावर एक operation लागू करा), Observer (push विरुद्ध pull सेवन).
अंगठ्याचा नियम: जर client ला संग्रहातून फिरायचे असेल पण तो कसा साठवला आहे हे कळायला नको, तर iterator उघड करा. जर तो फक्त तुमच्या पूर्ण नियंत्रणातील सपाट array असेल, तर साधा loop पुरेसा आहे, तुम्ही न वापरणारा उपचार जोडू नका.
06 - केस स्टडीज

प्रत्यक्ष जगातील केस स्टडीज

Iterator पॅटर्न production कोडमध्ये जिथे दिसतो अशा तीन प्रातिनिधिक जागा.

📦

1 · Java Collections Framework

पॅटर्न: प्रत्येक संग्रहावर fail-fast external iterators

प्रत्येक ArrayList, HashSet, आणि TreeMap iterators उघड करते, त्यामुळे client कोड त्या सर्वांवर एकसारखाच फिरतो.

  • Iterable.iterator() ही factory method आहे जी वर्धित for loop पडद्यामागे कॉल करते.
  • Iterators एक modCount तपासणी ठेवतात आणि अनपेक्षित रचनात्मक बदलावर ConcurrentModificationException फेकतात.
  • ListIterator ही कल्पना मागे फिरणे आणि सुरक्षित in-place संपादनांसह विस्तारते.
✅ निष्पत्ती: एकच फिरण्याची पद्धत डझनभर data structures वर चालते, आणि loop दरम्यान चुकून बदल झाल्यास ते शांतपणे भ्रष्ट होण्याऐवजी मोठ्याने अपयशी होते.
🌿

2 · Paginated API आणि database cursors

पॅटर्न: दूरस्थ, असीमित स्रोतावर lazy iterator

एका client ला REST endpoint किंवा SQL cursor मधून लाखो records सर्व memory मध्ये न भरता प्रक्रिया करायचे असतात.

  • प्रत्येक next() पुढचे पान किंवा row तेव्हाच आणते जेव्हा consumer मागतो.
  • iterator paging tokens आणि network retries एका साध्या hasNext() loop मागे झाकतो.
  • Back-pressure नैसर्गिक आहे: client जितक्या वेगाने सेवन करतो तितकाच स्रोत ओढला जातो.
✅ निष्पत्ती: client स्थिर memory वापरून प्रचंड result sets stream करतो, data cache, disk की paged HTTP API मधून येतो याबद्दल अनभिज्ञ राहतो.
🧬

3 · Compilers मध्ये tree आणि graph फिरणे

पॅटर्न: एकाच रचनेवर अनेक iteration क्रम

compiler त्याच्या abstract syntax tree मधून वेगवेगळ्या टप्प्यांसाठी वेगवेगळ्या क्रमांनी फिरतो: pre-order, post-order, आणि breadth-first.

  • वेगवेगळे iterator classes एकाच node प्रकारावर प्रत्येक फिरण्याची strategy encode करतात.
  • Optimization passes tree ने त्याचे child pointers न दाखवता त्यांना हवा असलेला क्रम निवडतात.
  • नवीन फिरण्याचे क्रम नवीन iterators म्हणून जोडले जातात, विद्यमान passes तसेच राहतात.
✅ निष्पत्ती: एकच AST अनेक फिरण्याच्या strategies स्वच्छपणे आधार देते, आणि प्रत्येक compiler टप्पा घटक अगदी त्याला हव्या त्या क्रमाने वाचतो.
07 - उपयुक्तता

आधुनिक उपयुक्तता

जुनाट होण्यापासून दूर, Iterator जवळजवळ प्रत्येक आधुनिक भाषेच्या syntax मध्ये रुजलेला आहे. आज तो सहसा हाताने लिहिलेल्या classes ऐवजी अंगभूत protocol म्हणून येतो.

🔤 भाषा-स्तरीय protocols

Java चे Iterable, JavaScript चे Symbol.iterator, Python चे __iter__, आणि C# चे IEnumerable हे सर्व पॅटर्नला for-each syntax मध्ये प्रमाणित करतात.

⚙️ सोपे iterators म्हणून generators

JavaScript चे function* किंवा Python चे yield काही ओळींत lazy iterator बनवतात, जिथे position state तुमच्यासाठी runtime सांभाळतो.

🌊 Streams आणि pipelines

Java Streams आणि LINQ iteration वर map, filter, आणि reduce जोडतात, internal iterators ना composable data pipelines मध्ये बदलतात.

⏩ Async iteration

AsyncIterator आणि for await...of protocol ला कालांतराने येणाऱ्या data पर्यंत विस्तारतात, जसे sockets, event streams, आणि paged fetches.

🦀 Zero-cost abstractions

Rust सारख्या भाषा iterator chains ना runtime खर्चाशिवाय घट्ट loops मध्ये compile करतात, पॅटर्नला performance खर्च करावाच लागतो असे नाही हे सिद्ध करतात.

🧠 Reactive आणि pull विरुद्ध push

Reactive streams iteration ला ढकलल्या जाणाऱ्या events पर्यंत सामान्यीकृत करतात, आणि pull-आधारित iterator समजल्याने ती सीमा कुठे आहे हे स्पष्ट होते.

सारांश: Iterator पॅटर्न इतका पूर्णपणे जिंकला की तो भाषेतच विरून गेला. प्रत्येक वेळी तुम्ही for (const x of items) लिहिता तेव्हा तुम्ही तो वापरत असता, आणि खाली काय घडते हे जाणल्याने तुम्ही custom, lazy आणि async फिरणे आत्मविश्वासाने बनवू शकता.
