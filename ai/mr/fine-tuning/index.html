Fine-tuning · LoRA · PEFT

त्रासाशिवाय fine-tuning - LoRA आणि PEFT समजावून

एका base model कडे व्यापक कौशल्ये असतात, पण तुमचे वर्तन नसते. Fine-tuning तुमच्या task डेटावर model ला अद्ययावत करते जेणेकरून ते एखादी शैली, स्वरूप किंवा क्षमता आपोआप अंगीकारते. आधुनिक parameter-efficient fine-tuning (LoRA, QLoRA, adapters) हे संपूर्ण network ऐवजी जोडलेल्या weights च्या अगदी छोट्या संचाला प्रशिक्षित करून हे साध्य करते, त्यामुळे ते स्वस्त, जलद आणि सहज बदलता येण्याजोगे असते.

01 - काय

Fine-tuning म्हणजे काय?

Fine-tuning हे एका pretrained model चे प्रशिक्षण एका छोट्या, task-विशिष्ट dataset वर पुढे चालू ठेवते जेणेकरून त्याचे weights तुम्हाला हव्या असलेल्या वर्तनाकडे सरकतात. जिथे prompting हे inference च्या वेळी एका गोठलेल्या model ला दिशा देते, तिथे fine-tuning एक नमुना weights मध्येच रुजवते, त्यामुळे model प्रत्येक prompt मध्ये पुन्हा समजावून न देता योग्य सूर, स्वरूप किंवा निर्णय तयार करते.

🧊 Full fine-tuning

प्रत्येक weight अद्ययावत होते. सर्वात शक्तिशाली आणि सर्वात महाग - तुम्हाला संपूर्ण model memory मध्ये, मोठ्या GPUs आणि प्रत्येक task साठी सर्व parameters ची नवी प्रत लागते.

🪶 PEFT (LoRA, adapters)

Base weights गोठवली जातात; तुम्ही जोडलेल्या parameters च्या छोट्या संचाला प्रशिक्षित करता. बहुतेक tasks साठी तोच परिणाम, पण compute आणि storage चा फक्त एक अंश वापरून.

🎯 ते कधी जिंकते

वर्तन शिकवण्यासाठी उत्तम: सातत्यपूर्ण शैली, कठोर output formats, tool-use संकेत, किंवा एक संकुचित classification कौशल्य - नवी माहिती नव्हे.

02 - का

Parameter-efficient fine-tuning का अस्तित्वात आहे

एका मोठ्या model चे full fine-tuning म्हणजे अब्जावधी parameters अद्ययावत करणे, प्रत्येक task साठी संपूर्ण प्रत साठवणे आणि भरपूर GPU तास जाळणे. PEFT base गोठवून ठेवते आणि नव्या weights चा अगदी छोटा अंश प्रशिक्षित करते, ज्यामुळे संपूर्ण अर्थकारणच बदलते.

💸 प्रशिक्षणासाठी खूप स्वस्त

LoRA parameters च्या 1% पेक्षाही खूप कमी प्रशिक्षित करते, त्यामुळे ते एकाच GPU वर बसते. QLoRA गोठलेल्या base ला 4-bit मध्ये quantize करते, memory आणखी कमी करते जेणेकरून मोठी models माफक hardware वर fine-tune होतात.

📦 छोटे, बदलता येण्याजोगे artifacts

एक adapter काही दहा megabytes चा असतो, काही दहा gigabytes चा नव्हे. तुम्ही एक base model ठेवता आणि प्रति ग्राहक, सूर किंवा task अनेक adapters चटकन बदलता.

🛡️ Base अबाधित राहतो

मूळ weights गोठलेली असल्यामुळे, model त्याच्या सामान्य क्षमता टिकवते आणि सर्व काही अद्ययावत करण्याच्या तुलनेत तुम्ही catastrophic forgetting च्या सर्वात वाईट भागापासून वाचता.

⚡ विश्वासार्ह वर्तन, लहान prompts

एकदा एखादे स्वरूप किंवा शैली weights मध्ये राहू लागली, की तुम्ही प्रत्येक call वर लांबलचक few-shot prompts साठी पैसे देणे बंद करता - inference वेळी कमी latency आणि token खर्च.

सोप्या शब्दांत

उपमांसह fine-tuning समजावून

तीच कल्पना, चित्रित करण्याचे चार मार्ग, जेणेकरून तुम्ही कोणीही असाल तरी ती पटकन समजते.

🎓 विद्यार्थ्यासाठी

Prompting म्हणजे दर वेळी परीक्षेच्या पानावर सोडवलेली उदाहरणे देणे. Fine-tuning म्हणजे आधीच शेकडो प्रश्न सोडवण्याचा सराव करणे जेणेकरून पद्धत सवयीची होते आणि तुम्हाला यापुढे समोर उदाहरणांची गरज लागत नाही.

👩‍💻 डेव्हलपरसाठी

LoRA म्हणजे एका shared library वर बसवलेला patch किंवा plugin यासारखे आहे. तुम्ही संपूर्ण dependency fork करून पुन्हा compile करत नाही; तुम्ही वर्तन बदलणारा एक छोटा diff पाठवता, आणि प्रत्येक deployment साठी वेगळा patch load करू शकता.

🏢 व्यावसायिकासाठी

हा एक अनुभवी कर्मचारी एक छोटा विशेषीकरण अभ्यासक्रम घेत आहे असे आहे. त्यांना क्षेत्र आधीच माहीत आहे; एक नेमका अभ्यासक्रम तुमची घरगुती शैली आणि प्रक्रिया शिकवतो, जेणेकरून त्यांना प्रत्येक task साठी manual पुन्हा वाचावे लागत नाही.

🎸 रोजच्या भाषेत

एक कुशल संगीतकार एक setlist त्याची स्नायू-स्मृती होईपर्यंत सराव करतो. सर्वसाधारण प्रतिभा आधीच होती; सरावाने विशिष्ट गाणी पक्की होतात जेणेकरून सादरीकरण आपोआप होते.

03 - कसे

आतल्या बाजूने ते कसे काम करते

Fine-tuning चे दोन भाग असतात: एक offline तयारी आणि प्रशिक्षण pipeline जी एक adapter तयार करते, आणि एक inference मार्ग जिथे तो adapter गोठलेल्या base बरोबर चालून त्याचे वर्तन बदलतो.

📚 डेटा + प्रशिक्षण

स्वच्छ instruction / response जोड्या तयार करा, train आणि eval मध्ये विभागा, मग supervised fine-tuning चालवा. LoRA base गोठवते आणि प्रत्येक target layer साठी दोन छोट्या low-rank matrices शिकते.

🔌 Inference वेळी adapter

Serving वेळी LoRA weights गोठलेल्या base च्या activations मध्ये जोडली जातात. गणित म्हणजे W + (B·A)·scale, त्यामुळे छोट्या शिकलेल्या matrices मूळ model ला थोडे ढकलतात.

एका दृष्टिक्षेपात architecture

Architecture - डेटा एक छोटा adapter प्रशिक्षित करतो; serving तो गोठलेल्या base वर load करते

एक वास्तववादी LoRA / SFT प्रशिक्षण config

from peft import LoraConfig
from trl import SFTTrainer, SFTConfig

lora = LoraConfig(
    r=16,                 # rank of the low-rank update
    lora_alpha=32,        # scaling factor for the adapter
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)

args = SFTConfig(
    output_dir="out/brand-tone-lora",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,          # higher LR is fine for LoRA
    lr_scheduler_type="cosine",
    warmup_ratio=0.03,
    bf16=True,
    eval_strategy="steps",
    eval_steps=50,
)

trainer = SFTTrainer(
    model="mistralai/Mistral-7B-v0.3",
    args=args,
    peft_config=lora,            # freezes base, trains only LoRA
    train_dataset=train_ds,      # chat-format instruction pairs
    eval_dataset=eval_ds,
)
trainer.train()
trainer.save_model()             # saves ~tens of MB of adapter weights

लक्षात घ्या की फक्त LoRA matrices gradients वाहून नेतात - 7B base गोठलेला असतो. म्हणूनच जतन केलेला artifact इतका छोटा असतो आणि एकच GPU पुरेसा असतो, तर eval split run दरम्यान overfitting पासून रक्षण करते.

Fine-tuning ने नवी माहिती शिकवण्याचा प्रयत्न संथ, महाग असतो आणि शिळा होतो. माहिती retrieval मध्ये असावी; त्याऐवजी वर्तन, स्वरूप आणि शैलीसाठी fine-tune करा.

🗑️ गलिच्छ किंवा तोकडा डेटा

गोंधळलेली labels, duplicates आणि विसंगत formatting चुकीचा नमुना शिकवतात. एक छोटा, स्वच्छ, सुसंगत dataset दर वेळी एका मोठ्या गोंधळलेल्या dataset ला मात देतो.

🔥 Overfitting

खूप जास्त epochs किंवा खूप जास्त learning rate training set पाठ करते. Train loss घटत असताना eval loss वाढणे हे उत्कृष्ट धोक्याचे लक्षण आहे.

🧠 Catastrophic forgetting

संकुचित task वरील आक्रमक अद्ययावतीकरण सामान्य क्षमतेची झीज करते. Learning rates माफक ठेवा, PEFT ला प्राधान्य द्या, आणि काही सामान्य उदाहरणे मिसळा.

🎚️ चुकीच्या LoRA settings

Rank खूप कमी असल्यास वर्तन underfit होते; चुकीच्या modules ला लक्ष्य करणे किंवा प्रचंड alpha प्रशिक्षण अस्थिर करते. Rank, alpha आणि target modules विचारपूर्वक tune करा.

📏 खरे eval नाही

काही निवडक prompts वरून निर्णय घेणे regressions लपवते. एका held-out set आणि एका capability suite शिवाय तुम्ही सुधारणा नशिबापासून वेगळी ओळखू शकत नाही.

06 - केस स्टडीज

वास्तविक जगातील केस स्टडीज

Production-शैलीच्या वापरात fine-tuning दाखवणारे तीन प्रातिनिधिक नमुने.

🎨

1 · Brand सूर आणि स्वरूप adapter

नमुना: weights मध्ये रुजवलेली शैली आणि स्वरूप

एका marketing संघाला हवे आहे की प्रत्येक तयार झालेला snippet प्रत्येक call वर एका महाकाय शैली prompt शिवाय एका नेमक्या brand आवाज आणि मांडणीशी जुळावा.

  • काहीशे हाताने मंजूर केलेली उदाहरणे नेमका सूर, रचना आणि निषिद्ध शब्दयोजना टिपतात.
  • एक LoRA adapter हा आवाज model मध्ये प्रशिक्षित करतो जेणेकरून आता लहान prompts on-brand मजकूर तयार करतात.
  • Adapter प्रति brand version केला जातो, त्यामुळे एक base model अनेक घरगुती शैली serve करतो.
✅ निकाल: खूप लहान prompts सह सातत्यपूर्ण on-brand output, token खर्च कमी करून आणि few-shot दृष्टिकोनाला त्रस्त करणारी भरकटण्याची समस्या दूर करून.
🏷️

2 · एका मोठ्या model मधून classifier distill करणे

नमुना: एका मोठ्या teacher कडून एक लहान विशेषीकृत model

एक संघ support tickets label करण्यासाठी एक मोठे model चालवतो, पण मोठ्या प्रमाणावर प्रति call खर्च आणि latency खूप जास्त आहेत.

  • मोठे model tickets चा एक मोठा batch label करते, एक उच्च-गुणवत्तेचा training set तयार करते.
  • एक लहान base model त्या labels वर fine-tune केले जाते जेणेकरून ते निर्णय स्वस्तात पुनरुत्पादित करते.
  • मूल्यांकन पुष्टी करते की लहान tuned model held-out set वर teacher शी जुळते.
✅ निकाल: एक संक्षिप्त classifier जो मोठ्या model च्या खर्च आणि latency च्या एका अंशाने चालतो, मूळच्या जवळ अचूकतेसह.
🔧

3 · सातत्यपूर्ण tool-use आणि output स्वरूप

नमुना: एका agent साठी विश्वासार्ह structured output

एका agent ने कठोर JSON tool calls द्यायला हव्यात, पण base model कधीकधी भरकटते, ज्यामुळे downstream parser तुटतो.

  • योग्य tool calls च्या traces instruction आणि response training जोड्या बनतात.
  • Fine-tuning नेमके schema आणि calling संकेत शिकवते जेणेकरून वैध output हे मूलभूत होते.
  • कोणताही adapter पदोन्नत होण्यापूर्वी एक eval gate schema-वैध दर मोजते.
✅ निकाल: लहान prompts सह जवळपास परिपूर्ण schema पालन, ज्यामुळे पूर्वी ठिसूळ retry logic ची गरज असणाऱ्या parser अपयशांचे निर्मूलन होते.
07 - भविष्य

Fine-tuning कोणत्या दिशेने जात आहे

Adaptation एका जड प्रशिक्षण प्रकल्पाकडून जलद, composable, preference-जाणकार tuning कडे सरकत आहे.

🧩 Multi-adapter serving

Runtimes जे एका base वर अनेक LoRA adapters होस्ट करतात आणि प्रत्येक request योग्य adapter कडे पाठवतात, ज्यामुळे प्रति ग्राहक किंवा प्रति task models मोठ्या प्रमाणावर परवडणारी होतात.

🎛️ Preference tuning

DPO आणि त्याच्या उत्तराधिकाऱ्यांसारख्या हलक्या alignment पद्धती models ला वेगळ्या reward model शिवाय comparison डेटावरून थेट पसंतीच्या वर्तनाकडे tune करतात.

🪶 अधिकाधिक स्वस्त PEFT

QLoRA च्या पुढील प्रगती आवश्यक memory आणि वेळ कमी करत राहते, ज्यामुळे मोठ्या models चे fine-tuning सामान्य hardware वर येते.

🔗 RAG आणि tuning एकत्र

जिंकणारा नमुना माहितीसाठी retrieval आणि वर्तनासाठी tuned adapter यांची जोडी करतो, त्यांना एक-किंवा-दुसरे पर्याय म्हणून न मानता.

🧬 Adapter composition

Adapters विलीन करणे आणि रचणे यावरील संशोधन serve वेळी शिकलेली कौशल्ये मिसळण्याकडे निर्देश करते, modular, composable क्षमतांच्या अधिक जवळ.

🤖 स्वयंचलित डेटा निवड

Synthetic डेटा निर्मिती आणि स्वयंचलित filtering dataset - खरा अडथळा - बांधणे जलद आणि स्वच्छ ठेवणे सोपे करतात.

सारांश: fine-tuning हे तुम्ही एका सामान्य model ला तुमचे विशिष्ट वर्तन शिकवण्याचे साधन आहे, आणि PEFT ते स्वस्त, जलद आणि बदलता येण्याजोगे करते. जसे adapters लहान होत जातात आणि serving अधिक हुशार होते, तसे tuning हे प्रत्येक गंभीर AI उत्पादनातील एक नित्याचे, composable पाऊल बनते.
